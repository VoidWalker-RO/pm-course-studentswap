# Класифікація проєкту та аналіз його оточення

## 2. Аналіз внутрішнього оточення

* **Склад і компетенції команди.** Проєкт виконується одним студентом за погодженням із викладачем. Один учасник виконує ролі Project Manager, Product Owner, Developer, Designer та Analyst, тому всі рішення та основні етапи розробки залежать від однієї людини.

* **Технічні ресурси.** Для роботи використовуються персональний комп'ютер, середовище розробки, Git та GitHub. Додаткові платні ліцензії на цьому етапі не плануються.

* **Часовий бюджет.** Проєкт виконується в межах навчального курсу, тому основний час на розробку обмежений навчальним навантаженням та часом, який можна виділити на виконання лабораторних робіт. Орієнтовно на проєкт можна виділяти декілька годин на тиждень.

* **Досвід з обраною тематикою.** Проєкт потребує базових знань веброзробки, роботи з базами даних, GitHub та проєктування користувацького інтерфейсу. Частина необхідних технологій може потребувати додаткового вивчення під час розробки.

* **Організаційне середовище.** Проєкт виконується в межах університетського навчального курсу з управління проєктами. Робота організована самостійно, а результати окремих етапів перевіряються викладачем.

## 3. Аналіз зовнішнього оточення

* **Цільова аудиторія та її потреби.** Основною аудиторією є студенти, яким потрібно купувати або продавати вживані підручники, техніку, меблі та інші речі. Для них важливі доступна ціна, простий пошук товарів та можливість швидко зв'язатися з продавцем.

* **Аналоги та конкуренти.** Одним із аналогів є **OLX**, де користувачі можуть розміщувати оголошення про продаж різноманітних товарів. Іншим аналогом є **Facebook Marketplace**, який також дозволяє користувачам знаходити та продавати товари у своєму регіоні. StudentSwap відрізнятиметься орієнтацією саме на студентську аудиторію та її потреби.

* **Технологічні тренди.** На розробку продукту впливають поширення веб-застосунків, адаптивного дизайну, мобільного доступу та сучасних систем пошуку й фільтрації товарів. Також важливими є питання безпеки облікових записів та захисту даних користувачів.

* **Регуляторні та правові чинники.** Під час подальшого розвитку продукту необхідно враховувати вимоги щодо обробки та захисту персональних даних користувачів. Також потрібно враховувати правила розміщення оголошень та обмеження щодо товарів, продаж яких може бути заборонений або обмежений законодавством.

* **Партнерські системи та API.** На початковому етапі проєкт не залежить від обов'язкових сторонніх API або партнерських систем. У майбутньому можуть бути використані сторонні сервіси для авторизації, карт, зберігання зображень або інших функцій.

## 5. Висновки

StudentSwap є малим навчальним веб-проєктом у сфері e-commerce із середнім рівнем невизначеності вимог. Оскільки проєкт виконується одним учасником, доцільно використовувати ітеративний підхід: спочатку реалізувати основну функціональність, а потім поступово додавати та уточнювати окремі можливості.

Найкритичнішим внутрішнім чинником є обмеженість ресурсів, оскільки всі ролі проєктної команди виконує одна людина. Також важливими є доступний час та необхідність одночасно виконувати інші навчальні завдання. Зовнішнім чинником є потреби цільової аудиторії та наявність великих універсальних платформ оголошень, з якими продукт потенційно конкуруватиме за увагу користувачів.

На цьому етапі можна передбачити ризики, пов'язані з недостатнім часом на реалізацію всіх запланованих функцій, зміною вимог та необхідністю вивчення нових технологій. Додатковим ризиком є складність залучення користувачів, оскільки користувачі вже мають доступ до існуючих платформ для купівлі та продажу товарів.

Подальшими кроками є уточнення вимог до продукту, визначення пріоритетності функцій та створення початкової структури веб-застосунку. Після цього можна перейти до планування окремих етапів розробки та реалізації базової версії StudentSwap.
